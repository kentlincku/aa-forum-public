## 1. 現況

- 6 個頁面全是手寫 HTML＋內嵌 JS：聊天 1219 行、檔案 321、加入 agent 243、Skills 235、控制台 215、agent-control.js 178，共約 2400 行。
- 後端 FastAPI 共 75 個 API 路由，頁面直接 `fetch`。
- 現有 UI 測試是把 index.html 裡的函式抽出來給 node 跑（test_ui_enter_hp.py 等），改版後要換成元件測試。

## 2. 決定（皆採建議：React＋Vite＋TS、Tailwind＋shadcn/ui、靜態輸出由 FastAPI 提供、內部命名一起改）

### 2.1 前端框架

| 選項 | 優點 | 缺點 |
|---|---|---|
| **A. React＋Vite＋TypeScript（建議）** | 生態最大、開源貢獻者最多；元件庫選擇多（shadcn/ui、Radix） | 打包較大 |
| B. Svelte（SvelteKit 靜態輸出）＋TypeScript | 輸出小、寫起來簡潔 | 貢獻者池較小 |
| C. Vue 3＋Vite＋TypeScript | 上手容易 | 元件庫與 Linear 風格的現成資源較少 |

### 2.2 元件與樣式

- 建議：Tailwind CSS＋shadcn/ui（Radix 底層，無障礙處理好、樣式可完全改）。
- 主題用 CSS 變數（design tokens），明暗兩套，強調色一個變數可換。

### 2.3 部署形態

- **建議：建置成靜態檔，由現有 FastAPI 直接提供**（`web/dist`），使用者安裝時不需要 Node；只有開發者改前端時才需要 Node。
- 發佈時把建好的 `dist` 一起放進 release，`bin/aaf install` 不變。

### 2.4 頁面與資訊架構

| 現在 | 改版後（建議） |
|---|---|
| 登入 | Sign in |
| 控制台（首頁卡片） | Dashboard：團隊狀態、最近執行、待辦告警 |
| 群組頁／AA Forum（聊天） | Rooms：側欄群組列表＋訊息串＋右側成員面板 |
| 加入 agent | Agents：安裝、登入狀態、角色、每群工作階段 |
| Skills | Skills：清單、編輯器、分類包、指派、版本 |
| 傳檔站 | Files |

單頁應用，左側固定導覽列切換，網址用路由（/rooms/3、/agents/builder）。

### 2.5 命名清理範圍

- 介面文字全部換成 AA Forum 的英文用語＋中文翻譯檔。
- 程式內部名稱（`server/` 目錄、`bin/aaf`、環境變數 `AAF_*`（舊名已全部改掉，不保留相容））：
  - **選項 1（建議）：一起改成 aa-forum 的命名**，趁還沒開源一次改乾淨（`aaf` 指令、`AAF_*` 變數），舊變數名保留一段時間相容。
  - 選項 2：只改介面，內部名稱之後再說。

### 2.6 i18n

- 英文為預設，中文（zh-TW）為第一個翻譯；使用者在設定切換，記在瀏覽器。
- 後端回給使用者看的錯誤訊息目前是中文，要改成錯誤代碼＋前端翻譯（後端訊息改英文）。

## 3. 進行方式（確認後）

1. 先做 2～3 個靜態視覺稿（同一個聊天頁＋Dashboard，不同配色／密度）給你挑。
2. 定版後搭框架骨架、主題、導覽、登入。
3. 依序搬頁面：Rooms → Dashboard → Agents → Skills → Files。每搬一頁，舊頁面才移除。
4. 每頁都用瀏覽器實測，並補元件測試；後端 389 個測試維持全過。
5. 最後改內部命名（若選 2.5 選項 1）、英文 README、CONTRIBUTING、開源前的私有字樣檢查。
